# Управление API-ключами

Используйте мастер-ключ только для первичной настройки и аварийного
восстановления. Создавайте отдельный управляемый ключ для каждого приложения
или оператора: так доступ можно независимо ограничивать, отслеживать и отзывать.

## Создание и сохранение ключа

Для создания нужны права на запись:

```bash
curl --fail-with-body -X POST "${NODE_NEXUS_URL}/api/v2/api-keys/" \
  -H "X-API-Key: ${NODE_NEXUS_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{"name": "inventory-reader", "scope": "read-only"}'
```

Поле `key` с полным ключом возвращается только один раз. Сразу перенесите его в
хранилище секретов потребителя. Последующие списки содержат только
`key_prefix`: он позволяет распознать ключ, но не пройти аутентификацию.

## Срок действия и область доступа

Получите список через `GET /api/v2/api-keys/?page=1&size=20`, затем измените
ключ по UUID:

```bash
curl --fail-with-body -X PATCH \
  "${NODE_NEXUS_URL}/api/v2/api-keys/${KEY_ID}" \
  -H "X-API-Key: ${NODE_NEXUS_API_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{"scope": "read-write", "expires_at": "2026-12-31T23:59:59Z"}'
```

Поле `is_active: false` отключает ключ без удаления записи. Время окончания
задаётся в ISO 8601. Получив `401`, клиент должен заменить учётные данные, а не
повторять запрос бесконечно.

## Ротация и отзыв

Ротация без простоя:

1. Создайте новый ключ.
2. Сохраните его в менеджере секретов потребителя.
3. Обновите потребителя и проверьте успешные запросы.
4. Отключите старый ключ и убедитесь, что обращений с ним больше нет.
5. Отзовите его через `DELETE /api/v2/api-keys/{key_id}`.

Успешный отзыв возвращает `204 No Content`. Не используйте мастер-ключ в
повседневной автоматизации и не выдавайте один ключ несвязанным потребителям.
