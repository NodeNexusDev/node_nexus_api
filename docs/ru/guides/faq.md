# Частые вопросы

## Как добавить ноду?

[Создайте ноду](nodes.md) с SSH-учётными данными, затем
[проверьте подключение](nodes.md). Используйте
возвращённый UUID для всех последующих операций.

## Как выполнить команду на ноде?

Два способа:
- **Прямой:** `POST /api/v1/nodes/{id}/execute/` с `{"command": "..."}`
- **Шаблон:** [создайте шаблон](commands.md), затем `POST
  /api/v1/commands/{id}/execute`

Готовые рецепты: [шпаргалка](../reference/cheat-sheet.md).

## Чем команда отличается от скрипта?

**Команда** — одиночное SSH-выполнение (прямое или через шаблон с
параметрами). **Скрипт** — упорядоченный pipeline из нескольких шагов с
настройкой `stop`/`continue` при ошибке, с запуском на нескольких нодах.
См. [скрипты](scripts.md).

## Почему приходит 401?

API-ключ отсутствует, неизвестен, неактивен или просрочен. Проверьте
заголовок `X-API-Key` и состояние ключа через `GET /api/v1/api-keys/`.
См. [аутентификацию](authentication.md).

## Почему приходит 403?

Ключ действителен, но имеет scope `read-only`, а вы попытались выполнить
запись (POST/PATCH/DELETE). Используйте ключ `read-write` для изменения
состояния. См. [управление ключами](api-keys.md).

## Почему приходит 503?

Ошибка SSH-подключения к ноде. Проверьте:
- Хост, порт и учётные данные ноды
- Сетевую доступность с сервера API
- Проверку SSH host key (`SSH_STRICT_HOST_KEY_CHECKING`)
- Доступность Docker daemon (для Docker-операций)

См. [решение проблем](troubleshooting.md).

## Как использовать зашифрованный SSH-ключ?

Передайте приватный ключ в `ssh_key` и passphrase в `passphrase` при
создании или обновлении ноды. Passphrase хранится в зашифрованном виде
и передаётся SSH-серверу прозрачно. Пример:

```json
{
  "name": "srv",
  "host": "192.0.2.10",
  "port": 22,
  "connection_type": "ssh",
  "username": "ops",
  "ssh_key": "<приватный-ключ>",
  "passphrase": "passphrase-ключа"
}
```

Если ключ не зашифрован, поле `passphrase` можно не передавать.

## Почему приходит 429?

Превышен per-IP лимит запросов. Дождитесь сброса окна. Ответ содержит
заголовок `Retry-After` с количеством секунд до повторной попытки. По
умолчанию: 100 запросов за 60 секунд.
См. [аутентификацию](authentication.md).

## Как ротировать API-ключ?

Создайте замену, разверните её на потребителе, проверьте, затем отключите
старый ключ и отзовите его через `DELETE`.
См. [управление ключами](api-keys.md).

## Как запланировать скрипт по расписанию?

Скрипты поддерживают cron-расписания. Создайте расписание через API с
cron-выражением, списком node_ids и опциональным часовым поясом. Только
одна реплика выполняет jobs (advisory lock).
См. [скрипты и расписания](scripts.md).

## Как импортировать конфигурацию из другого экземпляра?

[Экспортируйте](../guides/configuration-import-export.md) ноды, команды и
скрипты, затем импортируйте в целевой экземпляр. Учётные данные
исключаются из экспорта, их нужно задать заново после импорта.

## Что означает «ready»?

`GET /ready` проверяет подключение к БД и восстановление расписаний.
Non-owner реплика может быть ready (обслуживать HTTP), не выполняя
scheduled jobs.
См. [health и readiness](../operations/health-and-readiness.md).
